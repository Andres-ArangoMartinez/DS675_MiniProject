Sí. Busqué en Kaggle y encontré varias opciones bastante más cercanas a **Control Engineering + ML + sistemas industriales** que las típicas competencias de clasificación de imágenes.

### La que más te recomiendo: Tennessee Eastman Process

El **Tennessee Eastman Process (TEP)** me parece casi perfecto para ti. Es un benchmark creado específicamente para **control y monitoreo de procesos industriales**. Simula una planta química con múltiples variables de proceso, actuadores, modos de operación y fallas. En Kaggle hay versiones con hasta **55 variables**, simulaciones normales y con fallas, y datasets orientados a fault detection y domain adaptation. :chatgpt-content-reference{index="0"}

[Tennessee Eastman Process en Kaggle](https://www.kaggle.com/datasets/afrniomelo/tep-csv?utm_source=chatgpt.com)

Yo lo convertiría en un proyecto de portfolio llamado algo como **“ML-Based Fault Detection and Diagnosis for an Industrial Process”**.

La gracia es que puedes mezclar lo que ya sabes como control engineer con lo que estás aprendiendo en ML:

`Process → Sensors → Controller → Actuators`  
`             ↓`  
`     ML Monitoring System`  
`             ↓`  
` Normal / Fault type / Anomaly`

Puedes empezar muy simple con PCA, Logistic Regression, KNN, Random Forest o XGBoost y después evolucionarlo hacia Isolation Forest, autoencoders, LSTM/Transformers o domain adaptation. El dataset tiene múltiples modos de operación precisamente para estudiar qué ocurre cuando la distribución del proceso cambia. :chatgpt-content-reference{index="2"}

Y hay un ángulo que creo que quedaría especialmente bien en tu portfolio: **comparar métodos clásicos de Process Control con ML**. Por ejemplo, `PCA + Hotelling T²/SPE` frente a `Random Forest/XGBoost` frente a un modelo temporal. Eso demuestra que no eres simplemente alguien aplicando sklearn: estás conectando **process dynamics + instrumentation + control + machine learning**.

---

### Otra excelente: Mettler Toledo Industrial AI Challenge — Drug Prophet

Esta competencia de 2026 ya terminó, pero el problema es excelente para practicar. Había que predecir la concentración final de penicilina usando únicamente la primera parte de un batch industrial de fermentación. El simulador incluye dinámica de biomasa, transferencia de oxígeno, viscosidad, pH, nutrientes y perturbaciones, junto con las acciones de control tomadas durante el batch. :chatgpt-content-reference{index="3"}

[Mettler Toledo Industrial AI Challenge — Drug Prophet](https://www.kaggle.com/competitions/mt-ai-innovation-challenge-drug-prophet?utm_source=chatgpt.com)

Esto es básicamente un problema de **soft sensor**:

\[
y(k)=\text{concentración que no puedo medir fácilmente}
\]

pero tienes

\[
u(k),x(k),x(k-1),\ldots
\]

y quieres aprender

\[
\hat y=f(x_{0:k},u_{0:k})
\]

Eso conecta directamente con **state estimation, observers, system identification y MPC**. De hecho, los organizadores plantean que esa predicción podría utilizarse para decidir si modificar anticipadamente la estrategia de alimentación/control de un batch. :chatgpt-content-reference{index="5"}

Para alguien de control, probablemente es el problema **más interesante conceptualmente** de todos los que encontré.

---

### SCADA Time Series Forecasting — activo

Encontré también una competencia de **SCADA / control de procesos** que aparece actualmente con unos **9 meses restantes**, aunque tiene la limitación de que es **por invitación**. El objetivo es predecir una señal industrial varias horas hacia delante para que un operador pueda detectar desviaciones entre el valor esperado y el observado. Se evalúa con RMSE. :chatgpt-content-reference{index="6"}

[SCADA Time Series Forecasting en Kaggle](https://www.kaggle.com/competitions/scada-time-series-forecasting?utm_source=chatgpt.com)

Desde control sería algo como:

\[
e(k)=y_{\text{SCADA}}(k)-\hat y(k)
\]

y disparar una alarma cuando

\[
|e(k)|>\delta.
\]

Es casi un **residual-based fault detection system**, pero reemplazando parte del modelo físico por ML.

### Robot Predictive Maintenance 2026

También hubo este año una competencia con un **robot de seis motores**, usando posición, temperatura y voltaje de cada motor para determinar si está funcionando normalmente. El objetivo era fault detection y se evaluaba mediante F1. Terminó el 3 de junio de 2026, pero sigue siendo muy buen material para reproducir como proyecto. :chatgpt-content-reference{index="8"}

[Robot Predictive Maintenance — Season 2026](https://www.kaggle.com/competitions/robot-predictive-maintenance-season-2026?utm_source=chatgpt.com)

Aquí podrías llevarlo más lejos que la competencia y modelar algo como:

\[
[V,I,T,\omega,\theta] \rightarrow \text{Health State}
\]

e investigar qué sensores permiten detectar una falla primero.

### Si quieres competir ahora mismo: SECOM Defect Detection

La opción abierta que encontré es **SECOM Defect Detection Challenge**, que muestra actualmente alrededor de **6 meses restantes** y permite unirse. Son cientos de sensores de un proceso de fabricación de semiconductores —temperatura, presión, voltaje, etc.— y hay que identificar productos Pass/Fail. :chatgpt-content-reference{index="10"}

[SECOM Defect Detection Challenge](https://www.kaggle.com/competitions/secom-defect-detection-challenge?utm_source=chatgpt.com)

Es menos “control” que TEP, pero es muy buena para **multivariate process monitoring**, feature selection, datos faltantes y detección de anomalías.

### Lo que yo haría en tu caso

Empezaría con **Tennessee Eastman** y lo convertiría en un proyecto progresivo conectado directamente con **DS675**:

**Fase 1 — ML básico**  
EDA → scaling → KNN → Logistic Regression → Random Forest → métricas.

**Fase 2 — Ingeniería de control**  
Visualizar PVs, MVs y perturbaciones → generar residuales → analizar respuesta temporal de cada fallo.

**Fase 3 — Process Monitoring**  
PCA / Hotelling \(T^2\) / SPE vs Isolation Forest / XGBoost.

**Fase 4 — ML temporal**  
Ventanas:

\[
X_k=[x(k-N),...,x(k)]
\]

para detectar **qué falla existe y cuándo comenzó**.

**Fase 5 — Proyecto fuerte de portfolio**  
Dashboard estilo SCADA mostrando planta, variables, tendencias, estado estimado, probabilidad de falla y diagnóstico.

Eso sería bastante más diferenciador para un **Control Engineer entrando en Machine Learning** que hacer Titanic/MNIST o datasets genéricos.

Si quieres, en el siguiente paso puedo tomar el **Tennessee Eastman Process de Kaggle y diseñarte el proyecto completo para DS675**, incluyendo qué variables usar, problema ML a formular, baseline, estructura del notebook y una progresión donde vayamos incorporando los conceptos del curso a medida que los aprendes.

También puedo vigilar Kaggle y avisarte cuando aparezca una competencia nueva de **industrial AI, SCADA, robotics, predictive maintenance o process control**.
