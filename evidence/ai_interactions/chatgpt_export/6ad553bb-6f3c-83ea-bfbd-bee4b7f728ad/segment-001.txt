### C. ¿Cómo funciona Gradient Boosting?

La ecuación de tu documento es:

\[
F_m(X)=F_{m-1}(X)+\eta h_m(X)
\]

En palabras sencillas:

1. El modelo comienza con una predicción inicial.
2. Calcula qué tan equivocada fue esa predicción.
3. Entrena un árbol de decisión para corregir parte de ese error.
4. Agrega esa corrección a la predicción anterior.
5. Repite el procedimiento con nuevos árboles.

El parámetro \(\eta\), denominado *learning rate*, controla cuánto influye cada árbol nuevo en la predicción final.

Tu propuesta contempla probar 100, 200 o 300 árboles con learning rates de 0.03 o 0.1, entre otros parámetros.

Estos valores todavía son **hiperparámetros propuestos**, no valores que ya hayan demostrado ser óptimos.

### B. Métricas para evaluar los modelos

Utilizarás principalmente:

**MAE (Mean Absolute Error)**

\[
MAE=\frac{1}{N}\sum_{i=1}^{N}|y_i-\hat y_i|
\]

Mide el error absoluto promedio de las predicciones.

**RMSE (Root Mean Squared Error)**

\[
RMSE=\sqrt{\frac{1}{N}\sum_{i=1}^{N}(y_i-\hat y_i)^2}
\]

Penaliza más fuertemente los errores grandes.

**Skill Score**

\[
Skill=1-\frac{MAE_{model}}{MAE_{persistence}}
\]

Sirve para determinar cuánto mejora tu algoritmo respecto al baseline de persistencia.

La diferencia está en que **tienes 6 variables originales (sensores), pero utilizas 12 mediciones históricas de cada una para hacer una predicción**.

En Machine Learning, cada medición histórica se convierte en una *feature* diferente.

## 1. Tus 6 variables originales

En BattLeDIM seleccionaste:

1. Presión n1
2. Presión n4
3. Presión n31
4. Nivel del tanque T1
5. Caudal PUMP_1
6. Demanda AMR_n1

Si utilizaras solamente las mediciones actuales, tendrías **6 features**.

Pero tu Milestone 2 propone utilizar también las mediciones anteriores.

## 2. ¿De dónde salen las 72 features?

Imagina que quieres predecir la presión de n1 a las **10:15 AM**.

En lugar de utilizar solamente los valores de las 10:00 AM, utilizas los últimos 12 registros de cada variable:

| Hora | n1 | n4 | n31 | T1 | PUMP_1 | AMR_n1 |
|---|---|---|---|---|---|---|
| 9:05 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 9:10 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 9:15 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| ... | ... | ... | ... | ... | ... | ... |
| 9:50 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 9:55 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 10:00 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |

<text color="secondary" size="xs">Cada ✓ es una medición que se utiliza como entrada del modelo.</text>

Entonces:

\[
\underbrace{6}_{\text{variables originales}}
\times
\underbrace{12}_{\text{momentos históricos}}
=
\boxed{72\text{ features}}
\]

Esto se conoce como **lag features** o *variables rezagadas*.

## 3. ¿Cómo las recibe Gradient Boosting?

El modelo no recibe una tabla de 12 filas para cada predicción. Recibe **una sola fila con 72 columnas**.

Por ejemplo, las primeras columnas serían:

| Feature | Significado |
|---|---|
| `n1_t` | Presión n1 a las 10:00 |
| `n1_t-5` | Presión n1 a las 9:55 |
| `n1_t-10` | Presión n1 a las 9:50 |
| ... | ... |
| `n1_t-55` | Presión n1 a las 9:05 |
| `n4_t` | Presión n4 a las 10:00 |
| `n4_t-5` | Presión n4 a las 9:55 |
| ... | ... |
| `AMR_n1_t-55` | Demanda a las 9:05 |

Así completas 72 columnas.

Y tu variable objetivo (*target*) sería:

\[
y = n1_{10:15}
\]

Es decir, utilizas las 72 mediciones históricas disponibles hasta las 10:00 para predecir un único valor a las 10:15.
